# Prior art: agents and human gameplay demonstrations

Research date: **2026-10-24**. This is an initial literature/project review,
not an approved architecture or implementation plan. Findings are authors'
reported results, not independently reproduced experiments. Live repository
links may change; pin revisions before adapting any implementation.

No packages, videos or datasets were downloaded for execution or training, and
no game was run. Source pages were read online. No external code was copied.

## Context

The intended platform prioritizes exploration and learning, starts with combat,
and leaves room for full runs. Compute preference is a local RTX 5090, then
Colab, then another cloud machine. Desired strategies include prompted LLMs,
later LLM fine-tuning, and recurrent neural agents. Human VOD extraction is an
additional project direction. The user clarified that there is no known existing
extractor to integrate and selected **Baalorlord Unedited on YouTube** as the
desired recording source (exact channel/video URL still to be verified). The
near-term task is to acquire and inspect one permitted VOD as a feasibility pilot,
not design a full pipeline now or block other learner work on it.

## LLM agents

### MiniStS / Language-Driven Play (2024)

- [Project and experimental descriptions](https://github.com/iambb5445/MiniSTS)
- [FDG paper DOI](https://doi.org/10.1145/3649921.3650013)

Uses LLMs as text-based agents in simplified headless combat, without run/map
progression. Compares model and prompting variants, recent-state examples and
action-result descriptions. The README reports worse performance with additional
recent examples and action-result descriptions in its experiments. These are
context-specific findings, not a general argument against memory. Full paper
access was unavailable during the review; no numerical win-rate claim is adopted.

**Lesson:** prompt/history complexity needs experiments, not assumptions. Study
interfaces and experimental methods, not another simulator's gameplay rules.

### Orak (2025; inspected revision April 2026)

- [Paper](https://arxiv.org/html/2506.03610v3)
- [Code](https://github.com/krafton-ai/Orak)

Includes original-game Ironclad A0 through structured state converted to text.
LLMs choose combat plays and card rewards; rules handle other decisions, including
potions. Studies reflection, planning, memory and supervised fine-tuning.

The main StS setting uses one fixed seed and three runs per setting; its
normalized progress scores are not win percentages. Fine-tuning experiments
used four 80-GB A100s, not a demonstrated single-5090 recipe. Improvements in
valid-action generation must be distinguished from stronger tactical decisions.

**Lesson:** separate response validity, gameplay quality and inference cost.
Partial LLM control is not evidence of autonomous full-run strength.

### SpireBench (October 2026)

- [Paper](https://arxiv.org/html/2610.12596v1)

Studies complete original-game play, principally Ironclad A20, with player-visible
text observations and game tools. Uses floor-local conversations, notes and
optional cross-run memory. The main comparison uses ten seeds per model and
consistently renamed game entities. Reported Heart wins are sparse: one model
records one in ten; others record none in that table.

Authors report that accumulated cross-run memories do not improve overall
performance and can contain incorrect advice. Multi-action execution includes
feedback and interruption; this is not permission to submit stale action indices.

**Lesson:** bounded context and inspectable memory are useful design patterns;
automatic reflection is an experimental option, not a proven upgrade. Small
samples, character/difficulty and reskin conditions matter when reading results.

## Traditional learning, recurrence and search

### Creating an AI for Slay the Spire (2021)

- [Developer retrospective](https://www.toypiper.com/creating-an-ai-for-slay-the-spire/)
- [Associated project](https://github.com/jahabrewer/decapitate-the-spire)

Documents unsuccessful PPO/A2C attempts, slow original-game interaction, sparse
rewards and confusing action semantics. A step penalty encouraged quick deaths.
The author narrowed the task toward isolated combat. VOD reconstruction is
discussed as future work, not an implemented dataset pipeline.

**Lesson:** keep early milestones measurable; verify throughput and reward
incentives. PPO is a reasonable candidate, not an established StS solution.

### Bottled AI (October 2024 benchmark)

- [Architecture and public-information statement](https://github.com/xaved88/bottled_ai)
- [Reported results](https://github.com/xaved88/bottled_ai/blob/main/docs/winrates.md)
- [Coverage limitations](https://github.com/xaved88/bottled_ai/blob/main/docs/capabilities.md)

Uses handcrafted priorities and combat graph traversal with about 40 scoring
quantities, not ML. Authors state that it uses only player-visible information.
Reported win rates span 20–52% across roughly 50 runs per character. The benchmark
table does not state Ascension; these must not be relabeled A20 or Heart wins.
The project documents incomplete content and inability to acquire Heart keys.

**Lesson:** interpretable non-neural references can be useful. Do not copy its
custom simulator or treat its result labels as equivalent to ours.

### sts-rl-agent (repository inspected October 2026)

- [Architecture, results and limitations](https://github.com/Jialeiv/sts-rl-agent)
- [Evaluation boundaries](https://github.com/Jialeiv/sts-rl-agent/blob/main/docs/evaluation.md)

A roughly 100k-parameter observation/candidate-scoring MLP, trained with
REINFORCE, controls non-combat decisions. Combat uses exact-state MCTS. The
README explicitly notes true future draw order in combat rollouts and exact RNG
export in its original-game bridge. Its fixed evaluation seeds were reused for
selection, so they are validation rather than untouched final evaluation.

**Lesson:** candidate-conditioned scoring is worth exploring. The hybrid's
headline performance is not a public-information baseline. A teacher with hidden
information can produce labels that a public-information student cannot infer.
Do not adopt its privileged search, simulator patches or original-game bridge.

### Deep Recurrent Q-Learning for Partially Observable MDPs (2015/2017)

- [Paper](https://arxiv.org/abs/1507.06527)

LSTM-based Q-learning on Atari and partially observed variants, not StS or PPO.
Shows temporal integration and robustness to degraded observations, without a
systematic learning advantage from recurrence in general.

**Lesson:** preserve the requested recurrent experiment, but compare it with a
feedforward policy and explicit public-history features. This review did not
establish a convincing StS1 GRU/PPO success precedent; that is a search limitation,
not proof that none exists.

## Human data and VOD extraction

### Targeted follow-up: two StS2 VOD-related repositories

After the user recalled seeing a repository, a more targeted GitHub repository
search found these related projects. Both target the sequel, not StS1. Neither
has been identified by the user as the remembered repository.

- [SolvingSTS2](https://github.com/DanielALievano/SolvingSTS2) advertises human
  YouTube gameplay → behavior cloning → PPO. However, direct inspection of
  [scripts/extract_frames.py](https://github.com/DanielALievano/SolvingSTS2/blob/master/scripts/extract_frames.py)
  shows its own explicit scaffold warning: `parse_frame()` always returns `None`,
  OCR is unimplemented and action labeling is a TODO. Frame sampling exists;
  end-to-end video-to-demonstration extraction is not established by that code.
  The README's trained-agent language is not evidence of completed extraction or
  achieved playing strength. No trained weights or evaluation report appeared in
  the inspected repository tree.
- [sts2-pilot-trainer / Runmobile](https://github.com/zachlandes/sts2-pilot-trainer)
  describes reconstructing a top player's public video into a decision history,
  then verifying/replaying it through the original StS2 engine. Its README
  identifies a NaveGreed run and describes actions read from the video one by one.
  This is a close video-to-history precedent, not demonstrated general automated
  VOD labeling or an ML demonstration corpus. It uses seeds and hidden-state
  verification for replay; those must not become actor/critic inputs here. No
  engine tooling, game assemblies or hidden-state artifacts should be imported.

The follow-up also found
[slay-the-spire-2-overlay](https://github.com/rsaeta/slay-the-spire-2-overlay):
its repository description mentions YouTube visual identification, while the
current README centers on a mod/bot framework and trace recording. The description
alone does not establish a functioning VOD extraction pipeline.

### LearnTheSpire (2018)

- [Project](https://github.com/kaijchang/LearnTheSpire)

Extracts card choices from local run logs and trains a feedforward imitation
classifier. It is not video extraction or combat-action reconstruction. The
README explicitly admits evaluating on training data and likely overfitting.

**Lesson:** structured human logs may provide a cheaper complementary source,
but their content, quality and rights need separate checks. Training accuracy
does not establish human-choice generalization or playing strength.

### Slay-I (2020-era project)

- [Training project](https://github.com/alexdriedger/SlayTheSpireFightPredictor)
- [Mod](https://github.com/alexdriedger/SlayTheSpireFightPredictorMod)

Reports training a fight-HP-loss predictor on over 325,000 fights from Spire Logs
and Jorbs. Also scores card additions, upgrades and removals. The README's
approximately ±7 HP statement is not a difficulty-stratified confidence bound.
It is an advisor/predictor, not an autonomous combat policy. Mentioning Jorbs as a
data source does not establish that videos were parsed or that data reuse is
permitted.

**Lesson:** auxiliary prediction tasks are worth considering separately from
action imitation. Predictive card comparisons do not establish causal benefits.

### Video PreTraining / VPT (2022; Minecraft, not StS)

- [Paper](https://arxiv.org/html/2206.11795v1)

Trains an inverse-dynamics model using paired video/input recordings, then uses
it to pseudo-label much more online video for behavioral cloning. The paper
reports 1,962 hours of paired recordings and about 70,000 hours of filtered online
video. This is not a labeling-free or single-GPU-scale recipe to reproduce.

The offline labeler can see frames before and after an action. An acting policy
must not receive future frames or information that was not yet visible.

**Lesson:** a smaller labeled corpus plus assisted annotation is more credible
than assuming raw VODs immediately become action demonstrations.

### Player Experience Extraction from Gameplay Video (2018)

- [Paper](https://arxiv.org/abs/1809.06201)

Extracts approximate event logs from video using learned visual mappings, tested
in a Mario clone, Mega Man and Skyrim. It does not establish StS action extraction
or exact executable replays. Recognizing an event and identifying its input action
are different problems.

**Lesson:** evaluate extraction accuracy separately from downstream policy skill.
High aggregate frame accuracy can conceal missed rare decision events.

## Proposed implications, not yet approved design

1. Keep the small shared environment/evaluation core and independent strategies.
   The user approved that direction; individual modules are not implemented.
2. Add demonstrations as a first-class optional learning input, usable for both
   neural behavior cloning and LLM fine-tuning. Keep on-policy rollout semantics
   distinct from imported demonstrations.
3. Treat VOD extraction as a separate project/workstream producing versioned,
   audited records with source timestamps, visible observations, semantic action
   candidates, confidence and unknown/occluded fields. A later importer establishes
   compatibility; do not force incomplete video observations into a complete gym
   schema or fabricate legal masks.
4. Preserve observation-time availability: later frames or commentary can help
   annotate labels but cannot become earlier actor/critic inputs. Narration is
   optional evidence, not guaranteed ground-truth reasoning or action intent.
5. As requested, begin with one permitted Baalorlord Unedited VOD and exploratory
   inspection of representative decisions. Defer full extraction-pipeline design.
   If a later annotated pilot is approved, measure action/target precision, recall,
   abstention, accepted coverage and audit time. Split by whole run; hold out
   creators/layouts where feasible. One VOD is not a meaningful final evaluation
   corpus or evidence of extraction generalization.
6. Abstain on ambiguous duplicate cards, targets, cuts and rapid sequences. No
   hidden draw-order/RNG reconstruction and no second rules engine for validation.
7. Do not assume arbitrary expert footage maps to the gym's currently exposed
   bounded combat content. Preserve broader data for later supported integrations
   or offline tasks without claiming simulator compatibility.
8. Review recording, platform, dataset, code and model rights separately before
   acquisition/training/redistribution. Public accessibility alone is not permission.
   [YouTube terms](https://www.youtube.com/static?template=terms) are one relevant
   access constraint; creator-supplied originals may simplify authorized acquisition.

No ready-made StS1 VOD-to-combat-demonstration dataset was established by this
review. The targeted follow-up did find StS2 video-reconstruction work and a
video-imitation scaffold, as distinguished above. No reviewed source establishes
a validated RTX 5090 model/backend budget.
Both remain investigation topics, not negative existence claims.
